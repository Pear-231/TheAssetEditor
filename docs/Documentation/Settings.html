Settings Reference

This page explains every setting in the settings window (File → Settings), grouped the same way they appear on screen: Application, Rendering, and Game Files.

Some settings changes require the tool to be restarted before they take effect.

Rendering

SettingWhat it does
3D camera mode Selects the camera control scheme used across all 3D editors in AssetEditor: AssetEditor style (the default) or Blender style. See the Camera Control page for details on both schemes.
Render engine background colour Sets the background colour of the 3D viewport used by the visual editors (Dark Grey, Legacy Blue, or Green).
Grid Size Sets the size of the reference grid shown in the 3D viewport of the visual editors.
Vertex Selection Colour Sets the colour used to highlight selected vertices when editing meshes. Entered as a hex colour, e.g. #FF7800.
Only load Lod0 for reference meshes When importing a reference mesh in the Kitbash tool, only imports Lod0 (the highest detail level) rather than every LOD level, in order to save memory.

Game Files

SettingWhat it does
Active game

This is the single most important setting in the tool. It tells AssetEditor which Total War game you are working with, which controls how pack files for that game are parsed:

  • Which pack file format version (PFH4, PFH5, etc.) is expected.
  • Which encryption keystream is used to decrypt encrypted pack entries (different games use different keystreams even when they share the same pack file format version - AssetEditor needs the correct game to decrypt these files correctly).
  • Which compression formats are supported/expected for that game.
  • Which Wwise/audio bank version and project ID apply, for the Audio tools.
  • Which model/animation format versions (RMV2, WSModel, animation slots) apply, for the 3D and animation tools.

If you load a pack file that does not appear to match the selected game (wrong pack format version, or encrypted content that doesn't decrypt to anything recognisable), AssetEditor will show a "Pack file game mismatch" warning. If you see this, double check that the correct game is selected here before loading that pack file again.

This also determines which packs get loaded automatically on startup (see "Load game files on startup" below) and which path (below) is used for that.

Load game files on startup When enabled, AssetEditor automatically loads all of the selected game's own pack files (from the path configured for that game below) every time the tool starts, so the game's data is immediately available without having to open it manually.
Show game WEM files Controls whether the game's own .wem audio files are shown in the PackFile explorer tree for CA (game) pack files. This only affects official game packs - .wem files inside mod packs are always shown regardless of this setting. Since a game's own audio packs can contain a very large number of .wem files, this is off by default to keep the file tree manageable; turn it on if you specifically need to browse or extract the game's own audio files.

Below these settings is a list of every supported game, with a text box and a "..." browse button for each one. Set this to the data folder inside that game's installation (e.g. C:\SteamLibrary\steamapps\common\Total War WARHAMMER III\data) so AssetEditor knows where to find that game's pack files.

Only the games listed here are actually supported by AssetEditor's pack file handling (format version, compression, and encryption). Selecting a path for a game is what makes "Active game" (above) and "Open game files" able to find and load that game's packs.

When browsing for a folder, AssetEditor does a quick sanity check and warns you if the folder you picked doesn't appear to contain any pack files or a manifest.txt, in case you selected the wrong folder.
